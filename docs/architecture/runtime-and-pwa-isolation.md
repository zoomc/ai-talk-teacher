# Runtime and PWA isolation

Production, Demo, and E2E are separate web distributions. Production and Demo
must be deployed under separate base paths (`/talk/` and the controlled
`DEMO_PATH`) or separate origins. A
single URL query parameter is not an acceptable mode switch because it would let a
production shell load simulation code and would mix service-worker scopes.

Each build has independent:

- compile-time provider selection;
- SQLite/IndexedDB database filename;
- secure-storage key prefix;
- TTS cache directory and cache key namespace;
- service-worker scope and app-shell cache generated by its base path. The
  compile-time `APP_BASE_PATH` must equal Flutter's `--base-href`; this keeps the
  app's runtime boundary and the generated worker boundary identical.

The application never stores API keys in `web/`, the service worker cache, a URL,
or a simulation fixture. Demo/E2E builds do not issue provider requests even if a
profile row or legacy bridge flag is present.

The Demo entry must be labelled and provide reset. Reset operates only when
`RuntimeConfig.isSimulation` is true; the production database is never targeted by
the Demo reset action. The deployment workflow checks both public entry points and
requires nginx `auth_basic` for the Demo path before declaring deployment healthy.

## PWA checks

```bash
flutter build web --release --pwa-strategy=offline-first \
  --dart-define=APP_MODE=production --dart-define=APP_BASE_PATH=/talk/ \
  --base-href=/talk/
flutter build web --release --pwa-strategy=offline-first \
  --dart-define=APP_MODE=demo --dart-define=APP_BASE_PATH=/talk-demo/ \
  --base-href=/talk-demo/
flutter build web --release --pwa-strategy=none \
  --dart-define=APP_MODE=e2e --dart-define=APP_BASE_PATH=/ \
  --dart-define=E2E=true
```

For each Production/Demo artifact, verify that `index.html`, bootstrap, version
metadata, and the generated service worker use the expected base path. E2E has
no service worker by design. Dynamic AI responses, authorization headers, keys,
and recorded audio remain outside the cache policy described in
`docs/architecture/pwa-cache-and-update.md`.
